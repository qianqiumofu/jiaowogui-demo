# 千人合成校园体验

所有姓名、学号、工号、邮箱及联系方式都是合成值。联系方式采用 `SYN-PHONE-0001` 一类非真实号码。本轮不增加依赖或表结构，迁移仍为单头 `0018`。

## 数据结构

- 1000 名学生，每人有可登录身份、学号、学院、专业、年级、班级、性别、住宿和合成联系方式。
- 5 学院：计算机、数学、物理、机械、人文；每学院 200 人，2 专业 × 4 年级 × 25 人，共 40 班。
- 10 楼栋，覆盖闵行 9 园区；一栋单一性别、每间最多 4 人；所有楼栋有模拟门点、终端与排班。
- 每学院一名总负责人、4 名辅导员（各负责 50 人）及一名思政教师（明确分配 40 人，与辅导员有交叉）；保留辅导员兼学生的双身份。
- 20 名宿管，10 栋各有白班/夜班；保留 A1 夜班阿姨 23:00 起代班 A2 的场景。
- 当前业务夜与过去 14 夜覆盖预约、改期、撤销、二维码成功、人工补录、无预约补录、领码未通行、终端失败与结果未知。历史未确认预约关闭后仍可查询；不产生超时通知。
- 小部分学生具有连续的正式返宿事实，用现有风险规则生成待跟进、已知悉、已解决三类事件。园区可主动查询，不列入推送收件人。

## 建议体验顺序

打开体验地址，先选择身份筛选器，或搜索下面的合成登录名。统一演示口令 `demo1234`。

| 账号 | 体验内容 |
| --- | --- |
| `auth_admin` | 校级工作台；按学院查教师，为学院负责人配置管理学院 |
| `college_admin` | 计算机学院 200 人；学院名册、报告和负责教师分配 |
| `college_admin_2`—`college_admin_5` | 数学、物理、机械、人文学院各自 200 人 |
| `counselor` | 计算机学院 50 名负责学生，可切换学生身份 |
| `counselor_2_1` | 数学学院第一位辅导员，仅见负责的 50 人 |
| `ideology_2` | 数学学院思政教师，仅见明确分配的 40 人 |
| `campus` | 园区工作台，全校统计、宿管账号、值班、规则维护 |
| `dorm` | A1 夜班阿姨；23:00 起有效代班 A2 |
| `dorm_a2_night` | A2 夜班；其他楼栋按相同命名登录 |
| `student` | 第 1 位学生，当前夜留空，可亲自预约、改期、撤销与核验 |
| `student_0201` | 数学学院学生；登录页下方可直接输入任一学生账号 |

学生序号 `0001`—`1000`；第 1 人使用 `student`，第 9 人沿用 `counselor` 双身份，其余使用 `student_序号`。学号由年级与学生序号生成，不能把登录名当学号。

领导页进入“管理工作台”，再进入职责管理：选择教师与职责 → 按学院/班级批量加入学生 → 核对新增/移除人数 → 保存。筛选不会清空其他班已选学生；保存替换该项职责的完整范围，并使目标教师旧会话失效。

园区全校查询默认统计最近 14 夜。阿姨今晚名单只显示当前夜；历史二维码与人工返宿到返宿记录选择前一业务夜查询。模拟时钟可在设置中推进 23:00、00:00、06:00，规则仍由服务端判定。

## 重建与运行

数据库首次创建后，可从仓库根目录运行 `./scripts/start-campus-experience.ps1 -ResetData`，一次装载并后台启动三进程；以后省略 `-ResetData` 保留体验操作。启动前确保 8001/5174 未被占用，进程号及日志写在被忽略的 `tmp/campus-*`。

保留原 `app.db.seed` 的 66 人固定测试场景；千人场景用独立入口，不改变原自动化测试夹具。重建会清空目标库，必须确认目标是合成体验库；原开发库可继续保留。

```powershell
$env:DATABASE_URL='postgresql+psycopg://demo:demo@localhost:5432/jwg_campus_experience'
$env:DEMO_CLOCK_FILE='F:\A_homework\交我归\tmp\campus-experience-clock.json'
$env:PYTHONPATH='apps/api'
# 首次使用先 createdb，并在 apps/api 执行 alembic upgrade head。
apps/api/.venv/Scripts/python.exe -m app.db.experience --reset
apps/api/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir apps/api --port 8001
# 另开同样数据库与时钟配置的终端：
apps/api/.venv/Scripts/python.exe -m app.worker.main --interval 5
# 前端另开终端：
$env:JWG_API_TARGET='http://127.0.0.1:8001'
npm --prefix apps/web run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

体验入口为 `http://127.0.0.1:5174`，原 5173/8000 服务和原开发库保留。worker 用现有调度循环消费消息；不会向外部邮箱真实发送。未知通行由模拟对账任务处理为预设失败，不伪造返宿。

## 本轮验收（2026-11-19）

- `make check` 的 Windows 等价三项均通过：真实 PostgreSQL 全量 pytest **250 passed**、前端类型检查及生产 build、契约自检（59 路径、88 数据结构、55 样例）。迁移为 `0018 (head)`，无新增迁移。
- 独立体验库实测：1000 学生、1779 预约、1017 正式返宿（704 二维码、313 人工），8 风险事件（3 待跟进、3 已知悉、2 已解决）。这些是固定生成算法在初次装载时的数量；体验操作与 worker 可改变运行态。
- 通过真实前端代理登录后：数学学院负责人读取 200 人、数学学院辅导员读取 50 人；校级教师列表 33 人和职责列表合计约 0.65 秒返回（本机单次观测，不是性能承诺）。
- 浏览器核对领导首页四项规模，并验证“原负责 50 人 → 按班加入 25 人 → 预览 75 人、新增 25、移除 0”；预览测试未保存，体验库初始负责关系保留。按钮对比度已按截图修正。
- 没有新增动作权限，不放宽学院或负责学生范围。数据库样本检查覆盖四人间、单楼栋单性别、学生负责全覆盖、学号唯一、正式返宿唯一与无超时任务。全部场景仍是模拟。
