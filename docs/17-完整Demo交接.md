# 完整 Demo 与分层权限交接（2026-11-19）

## 用户确认与实现

教师、学生是统一目录给出的基础身份，COUNSELOR / IDEOLOGY 等是管理部门授予的工作职责。不能靠前端切角色、修改岗位名称或普通授予接口伪造学籍、教师身份或校级管理员。

| 身份 | 登录来源 | 工作范围及管理能力 |
| --- | --- | --- |
| STUDENT 学生 | 模拟学校统一认证 | 本人预约、核验、住宿和正式返宿记录 |
| TEACHER 普通教师 | 同上 | 本人身份页；不自动拥有负责学生权限 |
| COUNSELOR 辅导员（含兼职思政） | 同上 | 明确分配学生的名册、报告、风险跟进和返宿记录 |
| IDEOLOGY 专职思政 | 同上 | 与辅导员相同业务动作，按明确分配学生收窄 |
| COLLEGE_ADMIN 学院总负责人 | 同上 | 获授学院内所有学生的情况；给本院教师分配负责学生与思政/辅导员职责 |
| AUTH_ADMIN 校级权限管理部门 | 同上 | 全校配置学院负责人及学院集合、职责与负责关系；不自动成为风险收件人 |
| CAMPUS 园区负责人 | 同上 | 园区查询、规则、宿管工号与代班管理；不接风险推送 |
| DORM_MANAGER 宿管 | R19 园区工号例外 | 固定管理楼栋与生效代班并集；名单、现场补录、纠错和负责风险 |

校级身份只能经受控启动数据配置，普通职责授予接口不能创建 AUTH_ADMIN。授权更新与撤销有审计，并使目标人员已有持久会话失效，重新登录取得新职责。学院不能把外院学生分给教师，也不能覆盖含外院学生的已有职责。

学生名册和授权页支持学院、专业、年级、班级、姓名/学号筛选；筛选只缩小可选结果，不自动授予范围。保存前载入已授予选择。学院负责人读取本院风险概览，但仅拥有管理身份不接风险推送。

标准启动方式参见运行手册。运行前设置 DATABASE_URL，迁移需在 apps/api 目录执行 `.venv/Scripts/python.exe -m alembic upgrade head`。全新且可丢弃的合成库才运行 seed，因为 seed 会重置目标库。

API：`apps/api/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir apps/api --port 8000`。
前端：在 apps/web 执行 `npm run dev -- --host 127.0.0.1`，默认 http://127.0.0.1:5173/ 。
worker：按运行手册启动单一 worker 入口；只有 worker 循环调度周期任务，API 不另建调度器。

新增 qrcode==8.2：约 45 KB 的纯 Python wheel，用于本地 SVG 编码；不需要 Pillow、不上传 token 给图片服务，可由兼容 SVG 编码器替换。token 明文只在领码响应出现，数据库存摘要，读核验状态不会重新返回 token。

## 关键闭环

1. 学生预约 → 服务端核验窗口和版本检查 → 模拟核验 → 持久化凭证一次消费与签码同事务 → 手机 SVG → 设备身份核销 → returns 唯一正式事实 → 本人/宿管/负责教师记录。
2. 设备 FAILED 不产生正式事实；UNKNOWN 持久化尝试并排对账，不恢复旧码；成功回执才写正式返宿。事件重放幂等，冲突结果拒绝。
3. QR 与人工补录统一写入 returns；独立证据追加，更正只追加，不覆盖原记录。更正时间必须在原业务夜且不能晚于服务器时间。
4. 日报/周报订阅与风险配置分离。风险基于正式返宿事实，投递时重查负责关系，只发负责教师与当班宿管，园区只读查询。无超时未返宿任务。
5. worker 业务键去重、过期租约重领、旧领取代次不可完成新任务、失败退避；延迟执行的零点快照按当时预约修订恢复。
