## 基准演示夜

种子脚本默认按演示时钟取「今天」作为业务夜，但两人的测试与交接文档都锚在 **`2026-11-15`** 这一夜
（`duty` 窗口、快照种子任务都跟着它走）。重置请用：

```powershell
cd apps\api
.venv\Scripts\python.exe -m app.db.seed --service-date 2026-11-15
```

不带 `--service-date` 直接重跑会把值班挪到真实当天，`tests/test_building_list.py` 里写死
`NIGHT = 2026-11-15` 的用例会立刻查不到收件人而失败。

同理，**服务端认为的「今晚」也要跟着对齐到基准夜**，否则园区端默认区间（当前业务夜往前 14 夜）
会往后踩进没有种子数据的夜里。偏移按「基准夜 − 今天」算，Git Bash：

```bash
BASE=2026-11-15
# 对齐到基准夜的正午：业务夜 D = [D 06:00, D+1 06:00)，落在 00:00 会被判成前一夜。
OFF=$(( ( $(date -d "$BASE 12:00" +%s) - $(date +%s) ) / 60 ))
curl -s -X POST http://127.0.0.1:8000/api/v1/demo/clock \
  -H 'content-type: application/json' -d "{\"offset_minutes\":$OFF}"
curl -s http://127.0.0.1:8000/api/v1/demo/clock   # 看 now 是否已落在基准夜
```

偏移只存在 API 进程内存里，**重启后端就回到真实时间**，要重推一次；要在基准夜的具体时刻演示
（23:50、00:10、06:00）就直接给对应分钟数，或者用「设置 → 操作指南」里的推进按钮。
worker 自己取系统时间，不读这个偏移——所以把时钟往前推过 7 天之后，旧导出会按保留期判 410，这是预期行为。

## 性别与排班范围

园区端筛选器与楼栋下拉会列出全校 107 栋，但下钻读数是 0，不会把有数的楼栋淹掉。
门点、终端与排班只在 `bldg_a1`/`bldg_a2` 落地：宿管范围仍是这两栋。
`directory.snapshot_buildings` 按「当日有在册住宿的楼栋」而不是整份目录排 24:00 晚归单，
否则每轮 worker 会写入 107 × 回看夜数条空任务，把日报、周报挤出 `claim_due_jobs` 的单轮批次。
迁移 `0008` 的回填规则与 seed 一致（学号序号奇偶），所以不重跑 seed 的库也能按性别查。

## 园区统计用的晚归历史

`app.db.seed` 默认在演示夜之前再写 14 个业务夜的合成返宿记录（`HISTORY_NIGHTS = 14`，`return_id` 前缀
`ret_hist_`），这样 `GET /statistics` 与园区页面能出真数字而不是满屏零。规律是确定性的，不依赖随机数：

- 只覆盖演示夜**之前**的整夜，`return_records` 里不出现演示夜本身，A 的当晚名单与报表断言不受影响。
- 每夜轮流取约 1/10 的学生（`(学号序号 + 夜序号) % 10 == 4`），每夜 6—7 人，14 夜合计 87 条。
- 学号序号能被 4 整除的记成「人工补录」（凌晨 00:40 前后，23 条），其余记成「扫码返宿」（凌晨 1 点后，
  64 条），所以来源筛选与「扫码 / 补录次数」两列都有对比值。
- 一学生一业务夜唯一，因此这些夜里**晚归夜数恒等于记录条数**，人数 ≤ 夜数；按片区/楼栋/年级/性别
  分组都能对上明细。
- 历史只落 `return_records`（B 是唯一写入方），不伪造预约与通行码：预约源现已接共享报告读模型；该历史区间没有预约时，园区端
  「预约」「未确认」两列为 0，`data_gaps=[]`。

演示不需要这段历史时用 `--no-history`；`make`/手动重跑 seed 会先清空全库（含 `export_jobs`），
之前发起的导出任务与 CSV 一并消失，这是预期行为。

园区端「按此口径导出」要看到结果，得有 worker 跑过一轮
（`(cd apps/api && .venv/Scripts/python.exe -m app.worker.main --once)`）：API 只登记 `EXPORT_BUILD` 任务，
渲染在 worker 里完成，CSV 存进 `export_jobs.csv_content`，保留 `EXPORT_RETENTION_DAYS`（默认 7）天。

首屏默认区间（当前业务夜往前 14 夜）能对出的数，实测两种姿势：

| 服务端认为的今晚 | 默认区间 | 人数 | 晚归夜数 | 返宿次数 | 扫码 / 补录 |
| --- | --- | --- | --- | --- | --- |
| `2026-11-15`（按上一节对齐时钟） | 11-02 ~ 11-15 | 62 | 81 | 81 | 58 / 23 |
| 真实日期 `2026-11-17`（没对齐） | 11-04 ~ 11-17 | 62 | 69 | 69 | 49 / 20 |

两种都足够说明「人数与晚归夜数不是一回事」；对齐时钟那一行数字更完整，正式演示按它讲。
