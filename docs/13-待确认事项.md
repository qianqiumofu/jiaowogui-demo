## 需要问学校或后续讨论

- 预警阈值、重复触发口径、弹窗频控与邮件周期的正式值。
- 日报、周报、23:30 名单的实际投递时刻，以及是否需要按收件人所在时区而非统一业务时区投递。
- 风险提示是否要求辅导员回执确认；当前 Demo 只在正文里说明「演示配置，不是校规」，不采集确认动作。
- worker 与 API 各自读一份时钟：演示时钟推进只影响 API 进程，worker 的到期判断仍用真实系统时间，
  所以把演示时钟推到 23:30 不会让周期任务提前投递。Demo 用 `deliver_now` 手动触发绕过，
  正式版需要共享同一份时钟偏移或改用数据库时间。
- 宿管工号账号是否一律由园区统一注册分发，还是允许楼栋主管分级创建；外包人员离场时的账号停用责任人与时限。
- 统一身份能否给出「学生／教师／外聘」标识，用于自动识别进入哪个工作台（R18）。
- 真实门禁型号与二维码/NFC 能力，扫码回执的证据等级约定。
- 核验供应商、精度要求与替代验证路径（定位不准或手机不可用时走人工确认）。
- 临时住宿、例外备案、补录回填与纠错权限。
- 敏感字段与导出范围、数据保留期与校内部署方式。
- 团队工期与演示规模。

## 怎么登记一条新的默认

1. 在 `业务规则基线.md` 的「Demo 工程默认」段落写清楚取值和理由，注明「非校规」。
2. 在代码里做成配置项，不写死在业务判断里。
3. 在 `contracts/openapi.yaml` 暴露需要的枚举或字段。
4. 加一条测试锁住边界值。
5. 提交说明中列出影响到的端点与页面。

**不存在超时未返宿提醒任务**：这条不是默认，而是已确认规则 R15，任何人不得加回。
