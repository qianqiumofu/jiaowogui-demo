# 提交前检查清单

复制一份到你的提交说明里，逐条打勾。不需要每条都跑全量，但对应类别必须覆盖。

## 每次提交

- [ ] 契约已同步（改了接口就要，未改写「无接口变更」）。
- [ ] `cd apps/api && ./.venv/Scripts/python.exe -m pytest -q` 全绿。
- [ ] `cd apps/web && npm run build` 全绿（含类型检查）。
- [ ] 涉及表结构时 `alembic upgrade head` 在本地库跑通，且只有一个迁移头。
- [ ] `git status` 中没有 `.env`、密钥、真实数据、`node_modules`、`.venv`、`dist`。
- [ ] 提交信息第一行是 `类型(模块): 摘要`，正文说明为什么这样改。

## 涉及权限

- [ ] 其他角色直接调该接口被 403，不只是前端隐藏。
- [ ] 辅导员只看到负责学生；宿管只看到有效值班楼栋。
- [ ] 园区的任何接口都不会收到风险推送；风险收件人只有辅导员与当班宿管。
- [ ] 一人多角色切换后，旧令牌立即失效。

## 涉及时间与通行

- [ ] 覆盖端点值：窗口内/恰好在端点/超出端点。
- [ ] 二维码 299 秒可用、300 秒失效，过期需重新核验。
- [ ] 06:00 之后使用旧码返回 `NIGHT_ACCESS_ENDED`。
- [ ] 一个学生一个业务日最多一条返宿记录。
- [ ] 超时与未确认路径没有产生任何通知任务。

## 涉及任务与消息

- [ ] 只有 worker 进程扫描任务表。
- [ ] 任务有唯一业务键、计划时间、租约、重试次数与最近错误。
- [ ] 重放同一回执不会重复放行；未知结果进入对账而不是恢复旧码。
- [ ] 邮件只进本地预览，未发真实消息。

## 涉及园区统计与导出

- [ ] 人数、晚归夜数、返宿次数三值分列，同一学生跨多夜时三者不相等且人数 ≤ 夜数。
- [ ] 归属口径可切 `snapshot` / `current`，两种口径都有断言，不共用一个数。
- [ ] 预约来源未落地时 `reservations`、`unconfirmed` 返回 `null` 并登记 `data_gaps`，不用 0 冒充。
- [ ] 其他角色调 `/statistics`、`/exports` 一律 403，前端隐藏只是顺带。
- [ ] 导出只出聚合列，CSV 里没有姓名、学号、手机号（R11 是结构性落实，不是靠删列）。
- [ ] 导出必须显式业务夜区间；`date_from > date_to`、未知 `params` 键在创建时就 422。
- [ ] 同一 `idempotency_key` 重复创建返回同一任务，不重复排队。
- [ ] 只有发起人能列出与下载；他人任务 404；未完成 409；过保留期 410 且内容已清空、任务行仍在。
- [ ] 统计与导出同一份口径的数能对上（页面数字与 CSV 合计逐行一致）。

## 演示相关

- [ ] 演示时钟可推进 23:50、24:00、06:00，不需要真实等待。
- [ ] 模拟标识（人脸、门禁、邮件）在界面上写明是模拟。
- [ ] 关掉模型服务，主流程仍能跑完。
