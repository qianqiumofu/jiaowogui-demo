# 查询与 CSV 下载排查

## 环境先对齐

- 用户确认统一保留千人体验：`http://127.0.0.1:5174`，代理 API 8001，数据库 `jwg_campus_experience`，使用 `scripts/start-campus-experience.ps1` 启动。Vite 默认端口与代理已统一，不自动顺延端口。
- 旧常规演示 5173/8000 已停用，旧数据库仅留存，不再启动第二套环境。仓库历史验收中的 5173 描述保留作历史记录。
- 导出范围字段依赖迁移 0020，删除字段依赖 0021；先备份保留的演示库，再在 `apps/api` 目录按该库的 `DATABASE_URL` 执行 `.venv/Scripts/python.exe -m alembic upgrade head`，不得重置演示数据。

## 查询速度

2026-11-19 定位到统计在调用报告读模型时，逐预约读取目录标签，一次月度查询约 1780 条预约产生大量独立连接和查询。目录领域服务新增本次调用内的批量标签上下文，统计通过该服务复用标签，不跨模块直接查表、不跨请求缓存、不改变计数和授权。

本机千人体验同一业务夜区间（2026-11-01 至 2026-11-18）API 实测从约 4771 ms 降为 1089–1508 ms；耗时随机器和区间变化，不作为固定性能承诺。数据库回归按标签 SQL 次数验收，避免用不稳定的毫秒门槛代替正确性验证。

API 自动重载与 worker 是不同进程；worker 加载过旧代码时，需按本地进程记录核对后重启对应环境的 worker，不能误停其他环境。

## CSV 中文乱码

后端输出 UTF-8 BOM（文件前三字节 `EF BB BF`）。`Response.text()` 会去掉 BOM；如果再将解码后的字符串存为文件，Excel 可能误判为系统编码。因此成功下载使用 `Response.blob()` 原样保存，只有错误响应才解码为文本并解析错误信封。

刷新浏览器后重新下载即可；下载到本地的旧文件不会自动修复。文件仍为既有六项聚合统计，不增加学生明细或联系方式。可先用文本编辑器按 UTF-8 打开旧文件核对，但正常的新下载无需手动选择编码。

回归：`node --test apps/web/tests/csv-download.test.mjs` 检查完整字节、BOM 与中文；真实 5174 下载也应检查前三字节，不能只检查 HTTP 200。
