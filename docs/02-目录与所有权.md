# 目录与所有权

一个仓库、一个后端应用、一套数据库。不要创建第二份前端或后端工程，也不要把两端拆成两个服务互调。

```text
交我归/
├── apps/
│   ├── api/                 FastAPI 后端与 worker
│   │   └── app/modules/     每个模块一个目录，负责人见 modules/README.md
│   └── web/                 Vue 前端，四角色入口 + 门口终端
│       └── src/features/    按角色分目录，跨角色公共件放 shared/
├── contracts/               OpenAPI 契约、样例与 SDK 生成说明（共同评审）
├── docs/                    本目录，操作说明
├── 业务规则基线.md           唯一业务规则来源
├── 技术路线.md               选型、数据与事务设计
├── 双人协作分工.md           责任表与交接契约
└── 详细路线图.md             阶段与验收
```

## 谁能改哪里

| 路径 | 主维护 | 另一人 |
| --- | --- | --- |
| `apps/web/src/features/student`、`counselor` | A | 只在 shared 层配合 |
| `apps/web/src/features/dorm-manager`、`campus`、`gate-demo` | B | 通过 shared 提需求 |
| `apps/web/src/shared` | A | B 提小 PR |
| `apps/api/app/modules/{identity,authorization,reservation,verification,risk,reports,notification}` | A | 评审 |
| `apps/api/app/modules/{directory,access,returns,building_list,statistics,exports,duty}` | B | 评审 |
| `apps/api/app/worker` | A 主责，B 注册自有处理器 | 不各自起调度 |
| `apps/api/alembic/versions` | 各模块负责人编写 | B 统一合并为单一迁移头 |
| `contracts/` | 接口负责人维护 | 共同评审 |
| 根 `README.md`、`.env.example`、`docker-compose.yml`、`.gitignore` | A | 改动需说明 |
| `apps/api/requirements*.txt`、`apps/web/package*.json` | A | 加依赖须附锁定版本 |

跨模块调用只能通过领域服务函数（同进程内），不得用 HTTP 调对方模块，也不得直接查对方模块的表。

前端有两块例外挂在 B 的目录名下、由 A 编写和维护，改它们前先找 A：
`apps/web/src/features/campus/views/StaffAccountsView.vue`（宿管工号账号，R19）与
`NotificationDemoView.vue`（演示投递与任务状态）。两者只做 A 自己接口的展示，
`InboxView.vue` 在 `features/shared/` 下，四端共用。
## 目录里的两级归属

- 片区：`organizations` 中 `org_type = CAMPUS_PARK` 的行（闵行 9 个片区），楼栋用 `buildings.campus_org_id` 归属片区；目录只登记不判断。
- 人口属性：`students.gender`（`MALE` / `FEMALE`）与 `grade`、`college_org_id` 一起构成园区端筛选维度（基线 R14）；实际取值由学校目录适配器映射（R02），演示值见 `docs/10`。
