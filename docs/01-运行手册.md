# 运行手册

本机已验证可用的版本组合，另一台机器请对齐大版本，小版本由锁文件决定。

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | 24.16.0 | 前端构建；`node -v` 应为 24.x |
| npm | 11.13.0 | 依赖用 `package-lock.json` 锁定 |
| Python | 3.13.12 | 后端与 worker；Windows 用 `py -3.13` |
| PostgreSQL | 17（容器） | 由 `docker-compose.yml` 启动 |
| Docker Desktop | 29.x，Linux 引擎 | 需要先手动启动 Docker Desktop |

## 第一次准备

在 PowerShell 或 Git Bash 里执行，可重复运行，不会破坏已有数据。

```bash
# 一次性：依赖与环境文件
cd "F:/A_homework/交我归"
docker compose up -d postgres
cd apps/web && npm ci && cd ../..
cd apps/api && py -3.13 -m venv .venv
apps/api/.venv/Scripts/python.exe -m pip install -r apps/api/requirements.lock.txt
copy apps\api\.env.example apps\api\.env
```

Git Bash 中把 `copy` 换成 `cp`。`apps/api/.env` 只放本地合成口令，永远不提交。

## 每天开工

```bash
# 1) 数据库（Docker Desktop 已启动时）
cd "F:/A_homework/交我归"
docker compose up -d postgres

# 2) 后端（单独开一个终端窗口）
cd apps/api
./.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000
# Git Bash 里用：.venv/Scripts/python.exe -m uvicorn app.main:app --reload --port 8000

# 3) 前端（再开一个终端窗口）
cd "F:/A_homework/交我归/apps/web"
npm run dev
```

浏览器打开 <http://localhost:5173>，点任意合成账号即可进入。后端接口文档在 <http://localhost:8000/docs>。

## 交检之前的自检

```bash
cd "F:/A_homework/交我归/apps/api" && ./.venv/Scripts/python.exe -m pytest -q
cd "F:/A_homework/交我归/apps/web" && npm run build
```

两条都通过才算可以提交。`pytest` 出现 `FAILED` 时先读断言里的状态码，不要直接跳过测试。

## worker

```bash
cd "F:/A_homework/交我归/apps/api"
./.venv/Scripts/python.exe -m app.worker.main --once
```

worker 启动时是唯一允许扫描任务表的进程；API 进程内不启动任何定时器。
