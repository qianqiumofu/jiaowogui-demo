# 界面壳与占位约定

四角色共用同一外壳；下表按实际接口与页面标注各入口的可用状态（截至 2026-11-19，在册功能均已接通，二维码部分按用户要求暂缓进一步检查）。实现核对见 docs/16，最新验收见 docs/17。

## 现在长什么样

| 入口 | 路由 | 内容状态 |
| --- | --- | --- |
| 登录页 | `/` | 已可用：读取 `GET /auth/demo-accounts` 列出九个合成账号（student、teacher、counselor、part_time_counselor、ideology、college_admin、auth_admin、campus、dorm）；园区运行时注册的工号账号不在其中，走表单输入 |
| 学生 · 晚归预约 | `/app/student/reservation` | 已可用：当夜预约的创建、改期、取消、恢复与修改历史，走 `reservation` 接口；核验时段与状态由服务端 `verification` 块显示，核验出码经 `VerificationPanel` 走 `verification` 接口（本地 SVG 编码、服务端状态轮询）。二维码部分按用户要求暂缓进一步检查，但实现与测试已在 |
| 学生 · 我的记录 | `/app/student/records` | 已可用：本人各业务夜的预约列表与逐条留痕，走 `reservation` 接口；本人正式返宿记录走只读本人的 `GET /returns/self`（`MyRecordsView`），不再 403；住宿与身份走 `/me/residence`、`/me/profile` |
| 辅导员 · 负责学生 | `/app/counselor/students` | 已可用：完整负责学生名册（`StudentsView` + `directory/students`），支持学院/专业/年级/班级/姓名学号筛选，含未预约学生，后端按负责范围收窄 |
| 辅导员 · 日报与周报 | `/app/counselor/reports` | 已可用：当夜明细与逐夜汇总按需读取（缺省前一晚）；日报/周报各自独立订阅落 `report_subscriptions` 表，周期投递由 worker 排程（`reports/subscriptions`、`worker/scheduler`），排队后退订会阻止投递 |
| 宿管 · 今晚名单 | `/app/dorm/tonight` | 已实现：当夜名单 + 改期/撤销异动 + 门禁通行「已通行 X / 共 N 人」；已接 A 的真实预约源和共享通知 |
| 宿管 · 现场补录 | `/app/dorm/manual-entry` | 已实现：本楼栋名册检索 + 选人补录（带备注与幂等键），与扫码同一条唯一约束，重复提交不会多出一条返宿 |
| 园区 · 全校查询 | `/app/campus/query` | 已实现：学院/片区/楼栋/年级/性别/来源 + 业务夜区间筛选，人数·晚归夜数·返宿次数三值分列；分组固定按片区（全校合计在上方的三张卡片、逐夜在下方的明细表，页面不再提供「分组维度」下拉），可切换「发生时快照 / 当前名册」；「按此口径导出」走 `POST /exports` + worker，任务列表可刷新与下载 CSV |
| 共享 · 风险跟进 | `/app/shared/risk` | 已实现：`RiskView` + `risk/events`，GET 按负责范围列事件，ack/resolve 落审计与可读历史；只基于正式返宿事实触发，收件人只有负责教师与当班宿管，园区主动查询而不接风险推送 |
| 共享 · 返宿记录 | `/app/shared/records` | 已实现：按业务夜翻页，列二维码使用情况（待通行/已核销/已过期/已作废）与无码人工补录 |
| 门口终端（模拟） | `/terminal` | 已实现：选终端身份 + 粘贴令牌调 `POST /device/scan`，明确标注模拟、不会真实开锁 |
| 设置 · 操作指南 | `/app/settings`、`/app/guide` | 已可用：演示时钟推进、会话信息、全局使用说明 |

## 三种面板状态

`DataPanel.vue` 统一处理后端返回，不要各页面自己写一套错误样式：

| 后端返回 | 面板表现 |
| --- | --- |
| `200` + `items: []` | 「当前没有记录」占位，说明接口按契约返回空列表 |
| `200` + 有数据 | 渲染数据 |
| `501 NOT_IMPLEMENTED` | 「该能力尚未实现」并显示负责人与阶段 |
| `403 FORBIDDEN_ACTION` / `SCOPE_UNRESOLVED` | 「后端已拒绝此操作」并显示错误码 |
| 其他错误 | 显示 `code`、`message`、`request_id`，方便一起排查 |

> 说明：当前正常业务流程已不再返回 `501`。该状态只在 `building_list` 依赖缺失（`ImportError`）的降级兜底里出现（`source.py`、`notify.py` 的 `not_implemented("M2", ...)`）；面板保留这一渲染分支只为退化场景，不代表任何在册功能未实现。

## 顶栏会话入口

- 「切换账号」按钮常驻顶栏：先登出（会话已过期时视为已登出，不报错），再回到账号选择页。
- 角色 pill 只在账号拥有多个角色时出现；单角色账号不渲染任何 pill。
- 设置 → 退出登录与「切换账号」行为一致，登出后必定跳转到 `/`。
- 登录状态下访问 `/` 弹回当前角色工作台；带令牌刷新或直接输入 `/app/*` 地址都应正常渲染，入口先恢复会话再挂载路由。

## 文案规则

- 一个意思一句短话，正式语气，不写感叹号。
- 全局使用说明只放在「设置 → 操作指南」，页面里不重复解释同一件事。
- 二次确认使用非模态的展开面板，不要 `window.confirm`。
- 涉及模拟能力的地方必须写明「模拟」，例如模拟人脸核验、模拟门禁、模拟邮件预览。

## 布局与交互底线

- 学生按手机宽度设计（约 390px），宿管按平板宽度（约 1024px 横屏），园区与辅导员按桌面宽度。
- 次要筛选默认折叠，主操作保持单一焦点。
- 动效只用 240ms 左右的淡入与 4px 上移，并响应 `prefers-reduced-motion`。
- 新增页面在 `src/features/<role>/` 内，公共组件放 `src/shared/`；不要新建第二套布局壳。

## 导航项的显示条件

`src/features/shared/navigation.ts` 里每一项同时带 `roles` 与 `action`，两者都由后端给的
`/authz/actions` 结果决定，前端不做第二套判断：

- 「模拟收件箱」`shared-inbox`：`notification:read`，辅导员、宿管、园区都可见；面板只列自己的通知，
  展开正文、标记已读，不提供回复入口。
- 「演示投递」`campus-notifications`：`notification:dispatch`，只有园区可见；列出任务队列状态与
  `last_error`，投递走 `/notification-dispatch`，正文由 worker 消费后才出现。
- 「宿管账号」`campus-staff-accounts`：`staff_account:read`，只有园区可见。
