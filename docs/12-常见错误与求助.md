# 常见错误与求助

## 报错对照

| 看到的现象 | 多半是什么 | 怎么办 |
| --- | --- | --- |
| `docker: ... daemon ... not running` | Docker Desktop 没启动 | 手动启动 Docker Desktop，等图标变绿再重试 |
| `Address already in use: 8000` | 后端已在跑 | 直接用现有服务，或换 `--port 8001` |
| `ModuleNotFoundError: app` | 不在 `apps/api` 目录 | `cd apps/api` 再运行，或用 Makefile |
| `zoneinfo` 找不到时区 | 没装 `tzdata` | `pip install -r requirements.lock.txt` |
| `DATABASE_UNREACHABLE` | 容器没起或口令不对 | `docker compose up -d postgres`，核对 `.env` |
| `alembic ... Multiple head revisions` | 两人各写了迁移 | 别删对方文件，见下面「迁移多头」 |
| 前端请求 404 | 路径没带 `/api/v1` 前缀 | 检查 `api/client.ts` 与 `vite.config.ts` 代理 |
| 422 且字段名不符 | 用了 camelCase | 契约是 snake_case，改请求体 |
| `git: detached HEAD` | 直接 checkout 了提交编号 | `git switch -c tmp/名字` 保住改动，再切回分支 |

## 迁移多头

```bash
cd apps/api
./.venv/Scripts/python.exe -m alembic heads
```

出现两个头时：新建一个 merge 迁移把两条链并起来，保留双方文件，
```bash
./.venv/Scripts/python.exe -m alembic merge -m "merge a1 and b1" <头1> <头2>
```
然后 `upgrade head` 验证。B 负责最终合并，A 不代她决定。

## 怎么问一个问题（省时间）

按这四行写，对方基本一次就能答：

1. 我在做哪个功能，属于哪个模块（例如 `reservations` 改期）。
2. 我期望的规则是什么，引用基线条目编号（例如 R07 不限次数）。
3. 实际现象：报错码、状态码、`request_id`，或者哪个测试 `FAILED`。
4. 我已经试过什么（跑了哪条命令，看到什么输出）。

不要发「跑不起来」四个字加一张截图。

## 用 AI 写代码时的底线

- 生成的代码要能对应到基线某条规则，对不上的先问。
- 每次让 AI 改完，必须自己跑一遍 `docs/01` 的自检命令。
- 不许让 AI「顺手重构」对方主责的共享模块。
- 不确定的规则不要相信模型的记忆，回来查 `业务规则基线.md`。
