## 已补功能的使用位置

1. 园区 → 宿管值班指派 → “各楼栋晚归单与当夜负责人”：按业务夜、宿舍区、楼栋查询。汇总前人数为“待汇总”，不伪造0；正式返宿人数单独显示。负责人标明是汇总时保存、当前授权查询或旧历史不可追溯。
2. 园区 → 全校查询：查询后在片区行点击“查看楼栋”；查看同一条件下各楼栋人数、夜数及次数。区间包含连续14个业务夜日期时显示近7夜和前7夜变化；当前业务夜尚未结束时提示数值仍在变化。
3. 宿管没有授权楼栋时，顶栏不再称“全校授权范围”。

## 用户已确认的差异处理（2026-11-19）

用户确认“最后两个采用对方，其他按推荐”。下列选择已落实，不再列为待决定。

| 差异 | 最终选择 |
| --- | --- |
| 风险责任与代班 | 保留当前固定楼栋与有效代班范围；不排除代班 |
| 宿管风险办结 | 保留已优化的接手、跟进、办结流程 |
| 固定人员/楼栋排他 | 保留多账号管理同栋、一个人员管理多栋 |
| 代班前置主值 | 不增加“先有固定主值”硬门槛 |
| 人工补录时段 | 发生时间须为业务时区 [00:00,06:00)，可以白天补填历史；缺省业务夜按发生时间服务端派生。更正发生时间同样校验 |
| 零晚归分组 | 采用对方：有在册学生但无晚归也显示零行，统计与导出一致，仍需主动查询 |
| 培养层次 | 采用对方功能：本科、硕士、博士筛选，作用于人数卡、统计、下钻和导出；目录未同步的旧值只计入“全部” |

培养层次新增可空目录字段 education_level，迁移0019接在0018之后，不替换原有数据模型。演示种子明确写合成分类；本机66人与1000人体验库只补新字段，不重置预约、返宿、账号、职责。真实目录不得按学号或年级推导培养层次。
