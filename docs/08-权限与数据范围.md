# 权限与数据范围

原则一句话：**权限和范围都在后端判定，前端隐藏入口只是体验**。直接拿别的角色令牌调接口必须被拒绝，这是每次联调都要验的事。

## 现有底座

- `apps/api/app/modules/identity/schemas.py`：`Role`、`SessionContext`、`Person`。
- `apps/api/app/modules/authorization/policies.py`：动作到角色映射 `ACTIONS`，`is_allowed(...)`。
- `apps/api/app/modules/authorization/dependencies.py`：`require(action)` 依赖与范围缺失时的 403。
- 会话与范围解析：`apps/api/app/modules/identity/service.py` 的 `SessionStore` 与 `resolve_scope(...)`。
- 动作清单：`policies.ACTIONS`，新增动作必须同时写测试。
- 会话：模拟统一身份登录后签发，切角色会轮换会话并让旧令牌失效。

## 三个必须满足的判定顺序

1. 令牌有效（否则 401 `UNAUTHENTICATED`）。
2. 当前角色被授予该动作（否则 403 `FORBIDDEN_ACTION`）。
3. 结果集被 scope 限制（宿舍、负责学生、本人），范围缺失时 403 `SCOPE_UNRESOLVED`，不返回全量；
   指定了具体资源但不在范围内时 403 `OUT_OF_SCOPE`，`details.allowed` 回显当前范围。

## 角色能看什么

| 角色 | 范围 | 备注 |
| --- | --- | --- |
| 学生 | 只有本人 | 不能自行改归属楼栋 |
| 辅导员 | 只负责学生 | 负责关系由 B 的目录同步；缺失记配置异常 |
| 宿管 | 只有效值班楼栋 | 跨楼栋代班须有生效区间；失效后后端拒绝 |
| 园区 | 全校授权范围 | 主动查询预警，不接收风险推送 |

原始原因文本、联系方式、导出字段另设字段级权限，不能用角色一刀切放开。

## 联系方式怎么发

- 名单接口 `GET /buildings/{id}/tonight` **不返回** `phone`；阿姨在名单里点「联系」才走
  `GET /directory/students/{id}/contact`（动作 `contact:read_duty`，仅宿管）。
- 该端点先按有效值班楼栋校验，不在范围与学生不存在给同一个 `OUT_OF_SCOPE`，避免探测名册。
- 24:00 汇总后的异动推送是**唯一**在名单之外携带联系方式的通道：收件人由
  `directory.get_duty_staff(building_id, at)` 现算，只可能是当班人员，不允许扩到园区（R16）。

## 园区统计与导出的边界

- 动作：`statistics:read`（`GET /statistics`）、`campus:query`（`GET /statistics/filters`）、
  `export:create`（`POST /exports` 与本人任务的查询/下载），三者都只授予 `CAMPUS`；其余角色直接调一律 403。
- 园区是**全校范围**读，因此这里没有「按 scope 收窄」这一层，靠的是口径本身：统计读模型只出聚合数，
  联系方式与学生身份天然不在返回体里（R11）。
- 导出是「谁发起谁可下载」：`requested_by` 不等于当前用户时给 404 `EXPORT_NOT_FOUND`，
  不区分「不存在」与「不属于你」，避免探测别人的导出行为。
- 导出只接受统计读模型那 10 个口径参数，未知键创建即 422；范围不能通过导出悄悄变宽。
- 保留期（`EXPORT_RETENTION_DAYS`，默认 7 天）到点清空 CSV 正文、保留任务行做审计，下载改判 410。
  清空是立即提交的，不因随后抛出的 410 回滚。

## 风险投递的硬边界

风险事件的收件人只能是负责辅导员与当班宿管。任何新增的通知任务在投递前都要二次校验收件人范围，
**园区角色不得出现在风险收件人里**，这条要写成测试。

## 门禁终端不是会话用户

`POST /device/scan` 用设备身份认证：请求头 `x-device-id` + `x-device-token`，服务端只存 sha256 摘要，
匹配不到就是 401 `DEVICE_UNKNOWN` / `DEVICE_UNAUTHORIZED`。学生令牌调它一律无效，反过来设备凭据
也拿不到名单或返宿记录——那两页仍走会话与动作判定（`building:tonight`、`return:read_scoped`、
`manual_return:create`）。

终端只报告「这枚码在本门点被刷了」，放行与否、当夜名额是否已占用，全部由服务端按
`pass_codes` 与 `return_records` 判定；客户端传来的任何状态都不参与授权计算。
返宿记录页按角色收窄：辅导员只回负责学生，宿管只回有效值班楼栋，园区与学生拿不到该接口（403）。

## 加新接口时的做法

```python
@router.get("/buildings/{building_id}/tonight")
def tonight(
    building_id: str,
    context: Annotated[SessionContext, Depends(require("building:tonight"))],
) -> dict: ...
```

在 `resolve_scope()` 里补上该角色的数据边界，再在 `tests/test_identity_scope.py` 加一条越权断言。
前端可以调 `/authz/actions` 决定导航项是否显示，但不能代替后端判断。
