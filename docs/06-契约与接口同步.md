# 契约与接口同步

契约是两个人不打架的关键。规则一句话：**先改契约，再改代码；契约不同步就不算完成。**

## 命名与格式

- 前缀统一 `/api/v1`。
- 字段 `snake_case`；枚举大写字符串，例如 `ACTIVE`、`QR`。
- 时间一律带时区，例如 `2026-11-16T00:09:59+08:00`；日期用 `YYYY-MM-DD` 表示业务日。
- ID 是不透明字符串，长度和内容不承载含义。
- 列表响应统一 `{items, next_cursor}`；成功响应直接返回对象本身，不再包一层 `data`。
- 错误响应统一 `{code, message, request_id, details}`，`code` 用大写常量。
- 修改冲突返回 `409`，客户端重新拉取并提示用户，不自动覆盖。

## 改动流程

1. 在 `contracts/openapi.yaml` 增改路径与组件，补一个 `contracts/examples/` 样例。
2. 若契约变动会影响对方：在群里说清「加了什么、谁会受影响」，等对方确认再合并。
3. 删字段、改枚举含义或改语义，必须两人共同确认并提供迁移说明。
4. 同步实现与测试，前端把手写占位类型改成生成的 SDK 类型（见下）。
5. 一次提交里包含：契约 + 后端 + 前端调用点 + 测试。

## SDK 生成方案（2026-11-17 定案）

采用 `openapi-typescript`（仅 devDependencies，构建期生成、零运行时体积）：从
`contracts/openapi.yaml` 生成 `apps/web/src/shared/api/schema.d.ts`，请求层继续用
`client.ts` 自有封装，不引入生成客户端。

- 生成命令：`npm --prefix apps/web run generate:api`（已串入 `npm run build`，构建必过契约类型检查）。
- `apps/web/src/shared/api/types.ts` 只做稳定命名再导出；消费方一律从这里取类型。
- 生成的 `schema.d.ts` 提交进仓库；改契约后必须重新生成并一起提交，字段对不上会在 `vue-tsc` 阶段报错。
- 若日后要换成 `@openapitools/openapi-generator-cli` 完整客户端，属于共享层变更，需两人确认。

## 未实现接口怎么前后端并行

后端先用契约返回样例（约定用 501 `NOT_IMPLEMENTED` 或空列表作占位），前端按状态渲染占位面板。这是**尚未实现接口**的并行约定；当前在册功能均已接通，正常业务流程不再返回 501（仅 `building_list` 依赖缺失的降级兜底除外）。
不要凭想象造字段，也不要在前端造一份假数据当作业务结果。
